
# 🏎️ F1 Data Pipeline

ETL/ELT-пайплайн для автоматизированного сбора, хранения и анализа данных чемпионата Formula 1 из OpenF1 API.

Проект демонстрирует работу с данными: от получения информации через API и загрузки в PostgreSQL до создания аналитических витрин с помощью dbt.

## 📌 Возможности проекта

- Сбор данных из OpenF1 API.
- Загрузка исторических данных и обновление последних сессий.
- Автоматизация ETL-процессов через Apache Airflow.
- Хранение данных в PostgreSQL.
- Обработка данных с использованием Python и SQL.
- Создание аналитических витрин с помощью dbt.
- Автоматические проверки качества данных.
- Визуализация результатов в Metabase.
- Запуск проекта через Docker Compose.

Metabase используется для визуализации результатов.

## ⚙️ ETL-пайплайн

Данные из OpenF1 API загружаются в шесть таблиц PostgreSQL:

- `sessions` — информация о гоночных сессиях;
- `drivers` — пилоты и команды;
- `laps` — результаты кругов;
- `pit_stops` — данные о пит-стопах;
- `weather` — погодные условия;
- `positions` — позиции пилотов.

### Режимы загрузки данных

Предусмотрены два варианта работы:

**1. Загрузка истории**

Позволяет загрузить данные за выбранные сезоны Формулы-1, например за 2023–2025 годы.

Используется при первоначальном заполнении базы или когда необходимо повторно загрузить данные за прошлые сезоны.

**2. Обновление последних данных**

При регулярном запуске пайплайн выбирает сессии за последние 14 дней и обновляет информацию по ним.

Благодаря этому не нужно каждый раз заново загружать все предыдущие сезоны.

### Загрузка в PostgreSQL

Для сохранения данных используются:

- **UPSERT** — добавление новых сессий и пилотов или обновление уже существующих;
- **DELETE + INSERT** — замена старых записей выбранной сессии новыми;
- **Пакетная вставка** — загрузка нескольких записей за один запрос;
- **Транзакции** — отмена изменений в случае ошибки.

Это позволяет повторно запускать загрузку без накопления дубликатов из-за повторной обработки одной и той же сессии.

## 🔄 Apache Airflow

Для автоматизации ETL разработан DAG `f1_data_pipeline`.

Он состоит из семи последовательных задач:

```text
load_sessions
      |
      v
load_drivers
      |
      v
load_laps
      |
      v
load_pit_stops
      |
      v
load_weather
      |
      v
load_positions
      |
      v
run_dbt
```

### Возможности Airflow

- Автоматический запуск по расписанию.
- Ручной запуск загрузки исторических данных.
- Управление порядком выполнения задач.
- Повторные попытки при ошибках.
- Логирование и отслеживание статусов.
- Автоматический запуск dbt после завершения ETL.

Последняя задача `run_dbt` выполняет команду `dbt build`, которая обновляет аналитические модели и запускает проверки качества данных.

## 🗄️ Хранение и обработка данных

### RAW Layer

В PostgreSQL хранятся исходные данные, полученные из OpenF1 API.

Основные таблицы:

- `sessions`
- `drivers`
- `laps`
- `pit_stops`
- `weather`
- `positions`

Для работы с данными используются первичные ключи, индексы и транзакции.

### Staging Layer

Созданы шесть SQL-представлений:

- `stg_sessions`
- `stg_drivers`
- `stg_laps`
- `stg_pit_stops`
- `stg_positions`
- `stg_weather`

На этом этапе данные подготавливаются для дальнейшего анализа: приводятся к нужным форматам, очищаются и преобразуются.

### Data Marts

С помощью dbt разработаны шесть аналитических витрин:

| Витрина | Назначение |
|---|---|
| `mart_race_summary` | Общая статистика гонок |
| `mart_driver_performance` | Анализ результатов пилотов |
| `mart_team_comparison` | Сравнение команд |
| `mart_fastest_laps` | Анализ лучших кругов |
| `mart_pit_stop_impact` | Анализ пит-стопов |
| `mart_weather_analysis` | Влияние погодных условий на гонки |

Витрины формируются SQL-запросами и автоматически обновляются после загрузки данных.

## ✅ Data Quality

Для контроля качества данных настроена **41 автоматическая проверка dbt**.

Проверяются:

- Отсутствие пропущенных значений в важных полях.
- Уникальность идентификаторов.
- Корректность связей между таблицами.
- Допустимость значений отдельных категорий.
- Отсутствие повторяющихся кругов одного пилота в рамках сессии.

Также созданы две модели для выявления потенциальных аномалий:

- `dq_lap_anomalies` — необычные значения в данных о кругах;
- `dq_weather_anomalies` — необычные значения погодных показателей.

Проверки запускаются автоматически вместе с dbt.

## 🚀 Локальный запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/ddaria9876543/f1-data-pipeline.git
cd f1-data-pipeline
```

### 2. Настройка переменных окружения

Создать файл `.env` на основе `.env_template`:

```powershell
Copy-Item .env_template .env
```

Указать параметры подключения к PostgreSQL:

```env
POSTGRES_PUBLICIST_USER=postgres
POSTGRES_PUBLICIST_PASSWORD=your_password
POSTGRES_PUBLICIST_DB=f1_raw
```

Файл `.env` не должен публиковаться в GitHub.

### 3. Запуск контейнеров

```powershell
docker compose up -d --build
```

Проверить состояние сервисов:

```powershell
docker compose ps
```

### 4. Apache Airflow

Веб-интерфейс:

http://localhost:8082

Основной DAG:

`f1_data_pipeline`

Список задач можно посмотреть командой:

```powershell
docker compose exec airflow-scheduler airflow tasks list f1_data_pipeline
```

Ручной запуск DAG:

```powershell
docker compose exec airflow-scheduler airflow dags trigger f1_data_pipeline
```

Если DAG находится на паузе, для выполнения запуска необходимо снять его с паузы в интерфейсе Airflow.

### 5. dbt

Проверка подключения:

```powershell
docker compose exec dbt dbt debug
```

Запуск моделей и тестов:

```powershell
docker compose exec dbt dbt build
```

При обычной работе пайплайна dbt запускается автоматически через Airflow.
